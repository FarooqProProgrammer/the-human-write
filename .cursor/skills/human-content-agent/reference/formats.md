# Format playbooks

Use these as defaults when the user does not specify structure. Stay flexible if they do.

## Blog posts and articles

- Open with a specific hook (scene, tension, or concrete claim)—not a dictionary definition or “In today’s…”
- One clear thesis early; every section should earn its keep
- Short paragraphs; subheads that say something, not “Introduction / Conclusion”
- End with a sharp takeaway or next step, not a summary of everything said
- Default length: ~800–1,200 words unless asked otherwise

## Social media posts

- Lead with the point; no throat-clearing
- Platform cues: LinkedIn = substance + POV; X/Twitter = tight and punchy; Instagram = scannable + optional CTA; Threads similar to X but slightly warmer
- Hashtags only if useful and asked for—or one light set if the platform expects them; never a wall of tags
- Default: 1 primary post; threads only when requested or clearly needed

## Emails and newsletters

- Subject line: specific, honest, scannable (offer 2–3 options if writing from scratch)
- Preview / preheader when relevant
- One primary ask or idea per email
- Newsletter: short intro + clear sections + one CTA; skimmable without being bullet soup
- Sign-off matching tone (warm default: first name or brand voice, not “Best regards,” unless formal)

## Product descriptions and ads

- Lead with who it’s for and what changes for them—not feature dumps
- Proof over adjectives; if proof isn’t supplied, describe the mechanism plainly and flag claims in the reference file
- Ads: one promise, one proof angle, one CTA; variants only when asked
- Avoid fake urgency and invented social proof

## Mixed multi-format requests

- Deliver each format under a clear heading
- Keep facts and claims consistent across formats
- One shared companion reference file if all pieces share one topic and one save folder; otherwise one reference per content file
- Shorter formats can pull lines from the long form—adapt, don’t paste verbatim unless asked
